# M13 — Plan → Workflow Compiler & Execution Bridge

## Scope

M13 compiles an immutable M12 `AgentPlan` version into an immutable M8 `Workflow Definition`, then submits it through the existing durable Workflow Runtime. It does not create a second scheduler, worker pool, checkpoint store, event stream, lease system, or fencing mechanism.

## Execution flow

`Goal → AgentPlan(version) → Plan Compiler → Workflow Definition → Plan Execution Reservation → Workflow StartQueued → M8–M11 Runtime`

The bridge stores one reservation per `(goal_id, plan_version)`. Workflow and run IDs are deterministic for that Plan version. The reservation stores a SHA-256 digest of run input plus Agent Profile bindings. Repeating the same request reuses the same run ID; changing input or profile bindings for an already-started Plan version returns HTTP 409.

The reservation is written before workflow publication and queue submission. If the process stops after reservation, retrying the same request deterministically publishes the same definition and calls `StartQueued` with the same run ID. The existing workflow run insert and queue insert are idempotent. A reservation is not a claim that the run has completed; clients should poll the returned `run.id` through the existing Workflow Run API.

## Plan mapping

| M12 Plan step | M8 Workflow node | Mapping |
|---|---|---|
| `agent` | `agent` | Profile binding supplies `model_id` and managed `workspace_id`; prompt includes Goal, Plan objective, constraints, success criteria, step description and structured step input |
| `condition` | `condition` | `input.input_key`, `input.equals`, `input.true_next`, and `input.false_next` are required |
| `approval` | `approval` | Step description becomes the human approval message |
| `end` | `end` | Terminal node |

Each ordinary dependency becomes a DAG edge. Condition successors are explicit: `true_next` and `false_next` must refer to existing Plan steps, and a step declaring the condition as a dependency must be one of those branches. The existing M8 compiler performs final DAG validation, including reachability, cycles, edge handles, and terminal-node rules.

M8 originally had one entry node. M13 adds a pure `start` node to the Workflow domain/compiler/runtime for Plans with multiple independent roots. This node has no side effects and fans out to all root steps. Lease recovery treats it like the existing pure condition/end nodes.

## Agent Profile bindings

M13 does not introduce a persisted Agent Profile registry. The start request supplies `agent_profiles`, mapping each Plan `agent_profile` key to a registered `model_id` and an existing managed `workspace_id`. The bootstrap validator checks both against the current Model Registry and Workspace Manager. This keeps the Plan reusable while leaving profile management to a later milestone.

Example:

```json
{
  "input": {"ticket_id": "ISSUE-123", "approved": true},
  "agent_profiles": {
    "developer": {
      "model_id": "ollama-coder",
      "workspace_id": "project-workspace"
    }
  }
}
```

## Retry semantics

The current Workflow Runtime does not implement independent automatic retries for each Plan step. M13 maps the largest non-zero `step.retry_policy.max_attempts` to the existing Workflow job's **worker lease-expiry recovery ceiling**; if all steps leave it at zero, the configured Workflow queue default is used. This does not retry a failed Agent node. M11's node ledger, idempotency keys, and indeterminate-side-effect protection remain authoritative: an Agent node whose outcome may include external side effects is not automatically replayed just because the Plan requested a larger number. M13 does not promise exactly-once external side effects.

## API

`POST /api/v1/goals/:id/plans/:version/runs`

- `202 Accepted`: returns the Goal/Plan association, workflow ID/version, deterministic run ID, input digest, and current queued run snapshot.
- `404 Not Found`: Goal or Plan version does not exist.
- `409 Conflict`: the Goal is no longer active, or this Plan version was already reserved with different input/profile bindings.
- `422 Unprocessable Entity`: Plan cannot be compiled (invalid condition mapping, missing profile binding, invalid DAG, etc.).

The returned `run.id` can be queried through existing Workflow Run APIs. Workflow approval, SSE history, node observations, retry/recovery, durable queue processing, leases and fencing all remain in M8–M11.

## Database

Migration `000013_create_plan_executions` adds a unique reservation keyed by `(goal_id, plan_version)`, storing the immutable Plan ID, Workflow ID/version, Run ID, input hash and creation time. It deliberately does not add a second queue or checkpoint table.

## Non-goals

- Persistent Agent Profile CRUD/registry.
- Per-node automatic retry implementation.
- Goal success-criteria evaluation or automatic Goal completion.
- Reflection, long-term memory, autonomous replanning, or Plan mutation.
- New workflow scheduler/worker, event, checkpoint, lease or fencing implementation.
- Exactly-once guarantees for arbitrary external tool side effects.
