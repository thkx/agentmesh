# M4 — Tool System

## Scope

M4 provides a reusable tool execution subsystem. It does not implement an Agent Loop or let external Coding Agent CLIs call these tools automatically. Future runtimes can depend on `tools.Invoker` and share the same registry, policy, validation, and audit contracts.

## Architecture

- `internal/domain/tool`: tool metadata, JSON-schema subset, permission classes, errors.
- `internal/tools`: registry, argument validation, invocation engine, timeout and output limits, approval gate, audit contract.
- `internal/tools/policy`: configurable static policy implementation.
- `internal/tools/audit`: bounded in-memory audit implementation.
- `internal/tools/builtin`: filesystem, shell, and Git tools.
- `internal/transport/http/handlers/tools.go`: local HTTP management/invocation API.

## Built-ins

| Tool | Permission | Behavior |
|---|---|---|
| `file.read` | read | Read bounded UTF-8 text within workspace |
| `file.list` | read | List one workspace directory |
| `file.write` | write | Atomic create/replace, private file mode |
| `shell.exec` | execute | Direct executable invocation; exact executable allowlist |
| `git.run` | execute | Inspection-only Git subcommands |

Filesystem paths must be relative and remain within the resolved workspace root. File reads and writes have configurable byte limits. Shell execution never uses `sh -c` or equivalent. `allowed_commands` defaults to empty.

## Policy

Read is enabled by default. Write and execute are enabled but require `approved=true` on each invocation. This is a local single-user confirmation boundary, not a multi-user approval service. The HTTP listener must remain loopback-only because the current API has no authentication.

## HTTP API

- `GET /api/v1/tools`
- `POST /api/v1/tools/{name}/invoke`
- `GET /api/v1/tools/audit?limit=100`

Invocation body:

```json
{
  "workspace_id": "my-workspace",
  "arguments": {"path": "README.md"},
  "approved": false
}
```

`workspace_id` is resolved by the Workspace Manager; arbitrary filesystem paths are not accepted from the caller. The handler acquires a workspace lease for the duration of the invocation.

## Audit

Audit records include tool name, workspace path, allow/deny result, approval flag, duration, and error text. They never include raw argument bodies or tool output. M4 uses a bounded in-memory audit sink (default 2,000 events); persistence is deferred.

## Verification

Run with the repository's required Go toolchain:

```bash
gofmt -w internal/domain/tool internal/tools internal/workspace internal/transport/http/handlers/tools.go
go test ./internal/domain/tool ./internal/tools/... ./internal/workspace ./internal/transport/http/handlers ./internal/app
go test -race ./internal/tools/... ./internal/workspace
```

Acceptance cases include schema validation, unknown argument rejection, approval-required behavior, audit recording, workspace path traversal rejection, file read/write round trip, and shell executable allowlisting.

## Explicit limitations

- No external JSON Schema dependency; the validator supports object schemas with primitive property types, required fields, enums, and additional-properties control.
- No persistent audit table yet.
- Tool calls are exposed through the local HTTP API but are not yet wired into Claude/Codex/Gemini/OpenCode internal loops.
- OS-level sandboxing for shell commands is not provided by this milestone. Keep executable allowlists narrow and use the existing Docker sandbox for stronger isolation workflows.
