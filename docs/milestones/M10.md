# M10 — Workflow Runtime Distributed Execution Boundaries

## Scope

M10 strengthens the SQLite-backed Workflow Runtime for multiple processes sharing the same database file. It does not claim a distributed transaction with external tools/providers.

## Fencing tokens

- `workflow_jobs.fencing_token` is monotonically incremented on every successful claim.
- A `Job` carries the generation returned by the claim transaction.
- Heartbeat, finish, node intent creation, node completion, and run checkpoint writes validate owner + fencing token + unexpired lease.
- A stale process may finish an external request, but it cannot commit a node result or workflow checkpoint after another worker has acquired a newer generation.

## Lease renewal

- Worker heartbeat renews the run lease.
- The same heartbeat extends all running node ledger leases owned by that worker generation.
- Heartbeat failure cancels the execution context. The worker cannot finalize after losing its lease.

## Event stream backpressure

- SSE is pull-based from the durable event table; there is no unbounded per-subscriber in-memory queue.
- Each poll reads at most 32 events.
- The handler flushes each event and advances its cursor only after writing it.
- A five-second write deadline bounds slow-client stalls; clients resume using `Last-Event-ID`.

## Validation

- Migration 000011 adds fencing generations to jobs and node execution ledger.
- Checkpoint tests cover stale worker checkpoint writes, stale heartbeat, stale node begin/complete, generation monotonicity, and node lease renewal.
- SQLite migrations and the fencing SQL statements were smoke-tested with the system SQLite runtime.
- Full Go tests/build require the project's declared Go 1.27.3 toolchain. The current execution environment has Go 1.23.2 and could not download the required toolchain due DNS/network failure.

## Limits

Fencing protects writes to this SQLite database. It cannot revoke a network request already accepted by a third-party provider or tool. External side-effecting capabilities still need idempotency keys or downstream fencing support. SQLite remains a single-writer database; this milestone supports multiple worker processes sharing a database file, not multi-region active-active deployment.
