# M7 — Durable Agent Scheduler & Recovery

## Scope

M7 adds a SQLite-backed durable job queue, worker leases, lease heartbeats, restart recovery, bounded retry for failures that have not invoked tools, and a durable tool invocation ledger.

## Components

- `internal/agent/scheduler`: queue contracts, SQLite implementation, worker loop, and tool invocation ledger.
- Migration `000007_create_agent_scheduler`: `agent_jobs` and `agent_tool_invocations`.
- `POST /api/v1/agents/queue`: enqueue an Agent task and return HTTP 202.
- `GET /api/v1/agents/jobs/:id`: inspect queue status and lease metadata.
- `POST /api/v1/agents/jobs/:id/retry`: manually retry only a failed job with no recorded tool invocation.
- Existing `POST /api/v1/agents/run` remains synchronous for compatibility.

## Delivery semantics and safety

The queue provides durable at-least-once delivery before the execution-start boundary. Claim is transactional and lease ownership is checked on heartbeat and completion.

A worker crash after claiming but before `MarkStarted` allows the lease to expire and the job to be requeued, subject to `max_attempts`. Model/runtime failures are retried with exponential delay only while no tool invocation intent exists.

Once execution has started, an expired lease becomes `interrupted`; the scheduler never blindly replays it. This is deliberate: arbitrary tools can have external side effects, and a crash can occur after the side effect but before the result is persisted.

The tool invocation ledger writes an intent before invoking a tool. Completed invocations return the persisted result on duplicate calls. An invocation left in `started` state is `indeterminate` and is not executed again. This gives duplicate suppression, not mathematical exactly-once execution: an external side effect and local SQLite commit cannot be made one atomic transaction.

## Operational constraints

- SQLite is the durable queue and single-host coordination store.
- Multiple processes may claim jobs through atomic transactional claims, but should share a reliable local SQLite database file; do not place SQLite WAL databases on network filesystems.
- HTTP remains loopback-only until authentication and authorization are implemented.
- A job marked `interrupted` requires operator inspection. Do not force-retry if a tool may have produced a side effect.

## Configuration

```yaml
scheduler:
  worker_id: ""          # empty = hostname + PID
  poll_interval: 500ms
  lease_duration: 30s
  max_attempts: 3
```

## Validation note

The scheduler test suite is included in `internal/agent/scheduler/sqlite_test.go`, and runtime safe-retry tests are included in `internal/agent/runtime/runtime_test.go`. In the implementation environment, the project toolchain is Go 1.27.3 but only Go 1.23.2 is installed; downloading the required toolchain failed because network DNS was unavailable. The scheduler and config packages were compile-checked in a Go 1.23-compatible isolated module, the config tests passed there, and the migration/recovery SQL was smoke-tested with Python's SQLite. The Go SQLite integration tests and full-project test/build were not executed.
