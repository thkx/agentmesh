# M3 — Coding Agent Adapter

M3 adds a unified execution boundary for locally installed coding-agent CLIs. It does not implement a second Agent Loop: Claude Code, Codex CLI, Gemini CLI, and OpenCode retain responsibility for their own planning/tool loop. AgentMesh owns process lifecycle, request validation, workspace boundaries, timeout, cancellation, exit status, and normalized output.

## Frozen public contract

```go
type AgentExecutor interface {
    Execute(ctx context.Context, request execution.Request) (*execution.Result, error)
    Cancel(ctx context.Context, executionID string) error
}
```

HTTP endpoints:

- `POST /api/v1/executions` — run a coding agent synchronously.
- `DELETE /api/v1/executions/:id` — cancel an active execution.

Request fields: `id`, `provider` (`claude|codex|gemini|opencode`), `prompt`, `workspace_path`, optional `model`, `permission_mode` (`read-only|workspace-write`), and `timeout_seconds` (0 uses 30 minutes; maximum 24 hours at HTTP boundary).

Example flow:

```bash
# Create a private workspace under agent.workspace_root.
curl -sS -X POST http://127.0.0.1:8080/api/v1/workspaces \
  -H 'Content-Type: application/json' -d '{"id":"demo-run"}'

# Execute a CLI coding agent in that workspace.
curl -sS -X POST http://127.0.0.1:8080/api/v1/executions \
  -H 'Content-Type: application/json' \
  -d '{"id":"exec-001","provider":"codex","prompt":"Inspect this repository and summarize the architecture","workspace_path":"./data/workspaces/demo-run","permission_mode":"read-only","timeout_seconds":900}'

# A second request can cancel a still-running execution.
curl -i -X DELETE http://127.0.0.1:8080/api/v1/executions/exec-001
```

## Directory layout

- `internal/domain/execution`: provider, permission, request/result, status, validation.
- `internal/agent/executor`: stable executor interface.
- `internal/agent/executor/cli`: CLI adapter registry and orchestration.
- `internal/agent/executor/cli/process`: context-bound process runner and bounded stdout/stderr capture.
- `internal/agent/executor/cli/protocol`: JSON / JSONL output normalization.
- `internal/agent/executor/cli/{claude,codex,gemini,opencode}`: reserved provider-specific protocol extension points; command construction is currently centralized in `adapter.go` to avoid duplicated lifecycle code.
- `internal/workspace`: private local workspace directory manager.
- `internal/workspace/worktree`: Git worktree lifecycle.
- `internal/workspace/sandbox/docker`: opt-in Docker command runner with network disabled by default.

## Permission model

Permission defaults to `read-only`. `workspace-write` must be explicitly requested. AgentMesh does not expose a global bypass flag. Codex uses `--sandbox read-only|workspace-write` and `--ask-for-approval never`; Claude Code uses `plan|acceptEdits`; Gemini CLI uses `plan|auto_edit`; OpenCode runs in non-interactive JSON mode and selects its built-in `plan` agent for read-only requests. OpenCode's Plan agent still leaves shell command permissions to the user's OpenCode configuration. These are provider-native permission modes, not a universal OS-level sandbox.

## Security notes

- Commands are executed directly with `exec.CommandContext`; no shell interpolation is used.
- Workspace must exist, be a directory, and resolve inside the configured workspace root; symlink escapes are rejected. Active executions hold a workspace lease, so the API refuses to delete a workspace in use. Request prompts are passed as a single argument.
- stdout and stderr are capped at 8 MiB each.
- The HTTP API currently has no authentication. Keep the listener bound to `127.0.0.1`; do not expose execution endpoints to LAN or public networks.
- The Docker runner is an opt-in utility and is not silently inserted around host CLI processes. It disables networking by default, mounts only the requested workspace, and uses a read-only container root filesystem. A production deployment should explicitly configure a container image with the required CLI and credentials before using it as an execution backend.
- The HTTP host is now validated as loopback-only (`127.0.0.1`, `::1`, or `localhost`) while the API has no authentication. This prevents accidental LAN/public exposure through YAML configuration.

## Acceptance

```bash
gofmt -w internal/domain/execution internal/agent/executor internal/workspace internal/transport/http/handlers/execution.go
go test ./internal/domain/execution ./internal/agent/executor/... ./internal/workspace/...
go test ./...
```

The provider CLIs must be installed and authenticated separately. Their JSON/JSONL formats and flags evolve; verify local `--help` output when upgrading a CLI. Current command references: Claude Code CLI usage, Codex CLI reference, Gemini CLI headless mode, and OpenCode CLI run command.

## Scope boundary

M3 does not add a second model-driven Agent Loop or Tool Registry. Existing `ModelGateway` remains the API-model execution path; this milestone adds the external coding-agent CLI execution path behind the new `AgentExecutor` contract. Tool-calling API Agent orchestration remains a separate runtime milestone, rather than being approximated by a single chat-completion call.
