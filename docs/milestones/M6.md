# M6 — Native Tool Calling & Agent State Persistence

## Scope

M6 introduces a provider-neutral native function-call contract in ModelGateway and durable Agent task snapshots in SQLite. It keeps the M5 JSON-control protocol as a compatibility fallback for adapters that do not advertise native tool calling.

## Native tool contract

- `modelgateway.ToolDefinition` describes a function name, description and JSON Schema parameters.
- `modelgateway.ToolCall` carries provider call ID, tool name and JSON object arguments.
- `GenerateRequest.Tools` passes available tools to capable adapters.
- `GenerateResponse.ToolCalls` returns normalized native calls.
- Assistant messages retain tool calls; tool messages retain `tool_call_id` and tool output.
- Agent Runtime validates every call, checks LoopGuard, verifies the tool exists, then invokes the existing M4 Tool Engine. M4 authorization and approval remain authoritative.
- Ollama `/api/chat` native function calling and OpenAI Responses API function calling are implemented. Anthropic and Gemini adapters continue using M5's JSON control protocol in this milestone; they do not claim native capability yet.
- Streaming tool-call deltas are not implemented; Agent Runtime uses the non-streaming Generate path.

## State persistence

Migration `000006_create_agent_task_states` adds `agent_task_states`, storing a versionable JSON snapshot of Task, Result and the full Message transcript. SQLite upserts each snapshot as the run advances and at completion. The full transcript is retained separately from the trimmed message window sent to the model.

`agentstate.Store` is the persistence boundary. `SQLiteStore` implements it. Bootstrap attaches the store to Runtime. `GET /api/v1/agents/tasks/:id/messages` returns the persisted transcript; `GET /api/v1/agents/tasks/:id` can retrieve a result after the in-memory task cache has evicted it.

## Recovery semantics and limitations

- Completed and failed task state survives process restart and can be inspected.
- An interrupted `running` task is not automatically resumed. Resuming arbitrary tool executions is unsafe until tools have idempotency/replay semantics and the scheduler has durable ownership/lease handling.
- The current synchronous scheduler remains in-process. This is persistence, not a distributed queue.
- State persistence errors fail the task instead of silently claiming durable success.
- Transcript data may contain prompts and tool output. Protect the SQLite file and backups accordingly.

## Acceptance

- Native ToolCall validation rejects malformed IDs, names and non-object arguments.
- OpenAI Responses and Ollama Chat request/response mapping tests cover native tool calls.
- Runtime executes native tool calls through M4 Tool Engine and appends matching tool results.
- SQLite state round-trip test covers task, result and message history.
- Migration is embedded in the existing migration directory and is applied at startup.
